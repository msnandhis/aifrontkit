# Differentiation and defensibility

## Product thesis

AIFrontKit is the frontend system for production AI applications—not a gallery of chat components and not another AI backend SDK.

The product wins by combining five layers that are difficult to reproduce as a coherent system:

1. **Interaction breadth:** conversation, agents, tools, approvals, tasks, artifacts, research, sources, files, voice, structured output, long-running work, handoffs, computer-use status, generative UI, and multi-agent coordination.
2. **Behavior contracts:** explicit lifecycle states, commands, accessibility, interruption, recovery, responsive behavior, and deterministic fixtures.
3. **Designed variants:** genuinely different compositions for product contexts, built on shared behavior rather than duplicated implementations.
4. **Production decisions:** consistent answers for partial streams, failed uploads, expired approvals, tool errors, mobile citations, regeneration, background progress, disabled actions, and other expensive edge cases.
5. **Distribution knowledge:** registry metadata, typed contracts, examples, manifests, and agent-readable documentation that help both developers and coding agents install and compose the system correctly.

## What is centralized

Types, normalized events, state transitions, accessibility behavior, stream semantics, tokens, primitive contracts, and adapter contracts are maintained once.

## What varies at the edge

Layout, typography, density, visual treatment, motion recipe, component composition, workspace structure, and premium workflow depth may vary through source-owned registry items.

This turns breadth into product value without multiplying every behavior by every variant and framework.

## Free and Pro value

Community must be sufficient to build a real accessible AI product. Pro sells depth, composition, finished workflows, premium variants, application shells, and saved implementation time—not bug fixes, accessibility, adapter interoperability, or essential runtime behavior.

## Explicit non-goals

- Competing with AI SDKs, agent frameworks, model gateways, or orchestration systems.
- Claiming that streaming, shadcn compatibility, provider neutrality, or attractive chat bubbles are unique by themselves.
- Launching every framework, protocol, component, CLI feature, Studio feature, and distribution channel simultaneously.
- Adding MCP or another extension surface before registry metadata, CLI contracts, and real demand justify its maintenance and security cost.
